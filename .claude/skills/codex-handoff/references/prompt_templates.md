# Codex 검증 프롬프트 템플릿

이 파일은 codex-handoff 스킬이 생성하는 번들의 마지막 섹션에 들어갈 프롬프트 원본이다.
번들러 스크립트가 자동으로 삽입하므로 사용자가 직접 편집할 일은 거의 없다.
다만 프롬프트 톤을 조정하고 싶을 때 여기를 수정한 뒤 스크립트의 함수 본문(`_codex_prompt`,
`_doc_prompt`)을 동기화하면 된다.

---

## intent-skeleton (Claude가 1번 작성)

```markdown
### 변경 의도
- (1~3줄로 무엇을 왜 바꿨는지)

### 리스크 가설
- (어디서 깨질 수 있다고 의심하는가, 어떤 부작용이 가능한가)
- (각 가설은 검증 가능한 형태로: "X 입력에서 Y가 발생할 수 있다")

### 검증 포인트 체크리스트
- [ ] (Codex가 특히 확인해줬으면 하는 항목 1)
- [ ] (항목 2)
- [ ] (항목 3)
```

가능하면 **3개 내외의 가설**과 **5개 내외의 체크리스트**를 권장한다.
너무 많으면 Codex가 우선순위를 잃어 답이 산만해진다.

## code-review (번들 6번 섹션 본문)

```
당신은 venomhook 프로젝트(네이티브 바이너리/Android APK 정적 분석 + Frida hook 자동화)의
코드 리뷰어입니다. 위에 첨부된 번들은 Claude가 방금 적용한 변경의 최소 컨텍스트입니다.

다음 순서로 검토하세요:
  1) 1번 '작업 맥락' 섹션의 변경 의도와 실제 코드(2,3번)가 일치하는지 확인.
  2) 1번 '리스크 가설'을 실제 코드에서 찾아보고, 각 가설에 대해 [확인됨/문제없음/추가검토]로 답.
  3) 1번 '검증 포인트' 체크리스트 각 항목에 대해 [통과/실패/판단보류] + 근거 라인 인용.
  4) 가설 외의 잠재 버그/회귀: 변경된 함수의 호출자(4번 인접 파일 목록)와의 인터페이스 정합성,
     예외 처리, 입력 경계, 동시성 이슈, 보안 함의(특히 PoC 생성·Frida 스크립트 생성 경로)를 점검.
  5) 마무리: 머지 전에 반드시 고쳐야 할 항목(BLOCK)과 권장 개선(NIT)을 분리하여 결론.

응답 형식:
  ## 의도 일치성
  ## 리스크 가설 검증
  ## 검증 포인트 체크리스트
  ## 추가 발견
  ## 결론 (BLOCK / NIT)

근거를 인용할 때는 `파일경로:함수명` 또는 unified diff의 hunk 헤더를 사용해 주세요.
```

### 설계 의도

- **1→2→3 순서 고정**: Codex가 자유롭게 떠도는 대신, 사용자가 직접 작성한 가설을 먼저 검증하게
  하면 신호 대 잡음비가 높아진다.
- **BLOCK/NIT 분리**: venomhook은 보안 도구이므로 차단 사유와 단순 개선을 섞으면 머지 결정에
  방해가 된다. 두 그룹을 명시적으로 나눈다.
- **인용 강제**: "코드를 봤다"는 환각을 방지하기 위해 `파일:함수` 형태 근거를 요구한다.

## doc-verify (doc_verify.py 번들 4번 섹션)

```
당신은 venomhook 보안 컨설팅 산출물의 사실관계를 점검하는 리뷰어입니다.
위 1번 문서의 내용 중에서 2번에 추출된 주장 각각에 대해, 추정 출처(코드/스펙)와 일치하는지
검증해 주세요. 출처를 못 찾은 3번 항목은 모르면 모른다고 답하세요.

각 주장에 대해:
  - 일치: 코드/스펙이 문서의 진술을 뒷받침하는가?  (예/아니오/부분일치)
  - 근거: 어떤 라인·상수·함수가 근거가 되는가? (출처에서 인용)
  - 위험: 잘못된 진술이라면 어떤 오해를 일으킬 수 있는가?

응답 형식:
  ## 일치 (Confirmed)
  ## 부분 일치 (Partial)
  ## 불일치 (Contradicted)
  ## 판정 불가 (Unknown)

특히 venomhook 산출물 특성상 다음 항목은 보수적으로 보세요:
  - 룰 ID (MANIFEST-XXX 등)와 실제 룰 정의의 동기화
  - CLI 명령 시그니처와 cli.py의 argparse 정의
  - 수치 (룰 개수, 지원 ABI 수 등)와 코드 내 카운트
```

### 설계 의도

- **출처 매칭 결과를 그대로 활용**: 스크립트가 이미 후보를 좁혀 놓았으므로 Codex는 "확인" 작업에
  집중한다. 문서 전체를 스캔하라고 하지 않는다.
- **모르면 모른다고**: 보안 보고서에서 환각은 가장 큰 위험. 판정 불가 카테고리를 명시.
- **카테고리별 묶기**: 일치/부분/불일치/불가로 묶으면 사람이 한눈에 위험 항목을 찾을 수 있다.

---

## 변경 시 주의사항

이 템플릿을 수정한 뒤에는 반드시 `scripts/bundle.py`의 `_codex_prompt()`,
`scripts/doc_verify.py`의 `_doc_prompt()` 본문도 동기화해야 한다. 그렇지 않으면 번들에 들어가는
실제 프롬프트와 여기에 적힌 문서가 달라진다.
